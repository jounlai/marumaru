# 指示書：ひらがな棒人間「まるくん」作画アニメーション化（Codex 向け）

## 0. 前提と結論

現在の棒人間は **CSS のみ**で動いている（画像ゼロ・約 190 行）。骨格は
`頭＝の（丸い顔の輪郭の中にひらがな）／腕＝く／脚＝し／胴＝細い棒` で、歩行・ジャンプ・転倒・宙返りを
CSS keyframes で関節ごとに回転させている。

**画像化は必須ではない。** 現状でも歩行サイクル・溜め・つぶれ・起き上がりは表現できている。
この指示書は「手描きの気持ちよさが欲しくなったとき」に、**現行の CSS 版と差し替え可能な形で**
スプライトを作るためのもの。着手前に §7 の判断基準を読み、CSS で足りるならそちらを優先すること。

対象リポジトリ: `/home/jounlai/marumaru`
関連ファイル: `index.html`(棒人間のDOM) / `css/styles.css`(棒人間セクション) / `js/game.js`(`mascot*` 関数群)

---

## 1. キャラクター仕様

| 項目 | 内容 |
|---|---|
| 名称 | まるくん（仮） |
| モチーフ | ひらがなで組んだ棒人間。頭＝の、腕＝く、脚＝し（記号は使わない） |
| 画風 | 白 1 色の線画。線幅は均一（1.5px 相当）。塗りなし、影なし、アンチエイリアスのみ |
| 表情 | 顔の中身は**常にひらがな 1 文字**。待機中は「の」（へのへのもへじの目にあたる）。口・眉は描かない（怒り・驚きは体全体の姿勢で表す） |
| 頭の中身 | **描かない（空にする）**。待機中の「の」も、狙っているかな（例「さ」）も実行時にテキストで重ねるため、丸い輪郭だけを描き、内側は透明で中央に 10px 相当の余白が必要。<br>⚠ 輪郭を省いて「の」だけを頭にする案は**不可**（「し」など細いかなを狙ったときに頭が消えるため。検証済み） |
| 色 | 単色 `#fff` で描き、実行時に CSS `filter` で FEVER 色 `#7ef9d0`、被弾色 `#ff3b3b` に転ばせる。**色は焼き込まないこと** |
| 体型比 | 頭:胴:脚 ＝ 15 : 11 : 12（現行 CSS の実測値）。全高 36 : 全幅 26。頭と肩の間に 3px の首を空ける（腕を上げたとき頭に重ならないようにするため） |

## 2. 納品物

### 2-1. 形式（優先度順）

1. **SVG スプライト（最優先）** — 1 モーション 1 ファイル、`<symbol>` で全コマを内包
2. PNG スプライトシート — 上記が困難な場合のみ。透過 PNG、横一列、@1x/@2x/@3x
3. **APNG・GIF・動画は不可**（速度をコード側で制御できないため）

### 2-2. ファイル構成

```
assets/mascot/
  walk.svg     8コマ
  cheer.svg    8コマ
  fall.svg    10コマ
  spin.svg    10コマ
  idle.svg     4コマ
  README.md   （コマ順・推奨再生時間・ライセンス）
```

### 2-3. 画布とアンカー（厳守）

- 1 コマの viewBox: `0 0 26 40`
- **足の接地線は必ず y=40**（バーの上に立つため。コマごとにブレると歩行時に上下する）
- 横方向の基準は x=13（中心）。ジャンプ・転倒で中心から外れるのは可

## 3. モーション仕様

現行 CSS のタイミングをそのまま踏襲すること（ゲーム側の待ち時間と同期しているため）。

| モーション | コマ数 | 総尺 | ループ | 使用箇所 |
|---|---|---|---|---|
| `idle` | 4 | 3.4s | ループ | 何もしていないとき（呼吸） |
| `walk` | 8 | 0.92s | ループ | 正解して進捗が伸びる 0.5 秒間 |
| `cheer` | 8 | 0.8s | 1回 | 正解時・ラウンドクリア時 |
| `fall` | 10 | 1.5s | 1回 | 不正解時 |
| `spin` | 10 | 1.3s | 1回 | PERFECT 時 |

### 各モーションの演技指示

**idle** — 直立。肩と胸がゆっくり上下するだけ。顔の中身はコード側が描くので、輪郭だけを動かす。

**walk** — 右へ歩く。1 サイクル＝2 歩。
- 腕と脚は必ず逆位相（右脚が前なら左腕が前）
- 胴は 1 歩ごとに沈む（2 サイクル/1歩ではなく 2 回上下）
- 上体は進行方向へ 2〜3° 傾ける
- 接地の瞬間に軽くつぶれる

**cheer** — 正解の喜び。
1. 沈み込み（アンティシペーション、つぶれ）
2. 伸び上がって跳ぶ（ストレッチ、腕は**水平まで**）
3. 滞空
4. 着地でつぶれる
5. 立ち戻る
- ⚠ **腕を頭より上げないこと。** 頭に重なると小サイズで潰れて読めなくなる（実測で確認済み）

**fall** — 不正解。かなを弾き返された衝撃。
1. のけぞる（1〜2コマ）
2. 右へ倒れる
3. 尻もち＋小さくバウンド
4. **しばらく伸びている（コミカルな間）**
5. 自力で起き上がって立ち戻る
- 最終コマは必ず idle の 1 コマ目と同じ姿勢に戻すこと（そのまま idle に繋ぐため）

**spin** — PERFECT。踏み切って前方 2 回転宙返り、着地でためる。空中では手足を畳む。

## 4. 実装側の差し替え手順

現行の CSS アニメーションを消す必要はない。**画像が読めなければ CSS 版にフォールバック**する形にする。

### 4-1. 差し替え箇所

`index.html` の以下のブロックを丸ごと置き換える:

```html
<div class="mascot" id="mascot">
  <div class="mRig" id="mRig">
    <div class="mBob">
      <span class="mLeg mLegL">し</span> ... </div></div></div>
```

置き換え後（例）:

```html
<div class="mascot mascot--sprite" id="mascot">
  <div class="mRig" id="mRig">
    <svg class="mSprite" id="mSprite" viewBox="0 0 26 40" aria-hidden="true">
      <use id="mUse" href="assets/mascot/idle.svg#f0"></use>
    </svg>
    <span class="mHead" id="mHead">の</span>  <!-- 顔の中身は据え置き -->
  </div>
</div>
```

### 4-2. 触ってよい JS（`js/game.js`）

`mascot` で始まる関数だけを触ること。ゲームロジックには手を入れない。

| 関数 | 現在の役割 | 画像版でやること |
|---|---|---|
| `mascotPose(cls, ms)` | `#mRig` に `cheer/down/spin` を付ける | クラス付与に加え、対応スプライトの再生開始 |
| `updateMascot()` | 進捗に応じて `left` を更新、移動中 `walking` を付与 | `walking` 中は walk を再生、それ以外は idle |
| `mascotHead(text)` | 頭に狙っているかなを表示／無ければ「の」 | **変更しない**（顔の中身は現行のまま） |
| `mascotSay(text, kind, ms)` | 吹き出し | 変更しない |

コマ送りは `requestAnimationFrame` で行い、**`setInterval` を使わないこと**（タブ非アクティブ時にずれるため）。

### 4-3. 満たすべき条件

- `prefers-reduced-motion: reduce` のときはコマ送りを止め、idle の 1 コマ目を出す（既存のCSSに同指定あり）
- FEVER 時に色が `#7ef9d0` に変わること（`filter` か `currentColor` で）
- 画像取得に失敗しても**ゲームが動き続ける**こと（`onerror` で CSS 版へフォールバック）
- 追加アセットの合計は **60KB 以内**（現在ゲーム全体で約 120KB のため）

## 5. 検証（この手順で必ず確認すること）

リポジトリには Playwright ベースの確認スクリプトが既にある。同じやり方で目視確認する。

```bash
# 1コマずつ撮ってシート化する（既存スクリプトを流用）
node tests/mascot.js    # 各モーションをコマ送りで撮影（tests/shots/ に出力）
```

チェック項目:

- [ ] 歩行中、足が地面を滑っていない（接地足が画面に対して止まって見える）
- [ ] 全モーションで接地線が y=40 からズレない
- [ ] 腕が顔（かな）に重ならない
- [ ] 顔の中央にかなを重ねる余白が全コマで確保されている
- [ ] 26×40 の実寸（DPR 2〜3）で、何をしているか判別できる
- [ ] iPhone SE (375×667) / Android (360×640) で**縦スクロールが発生しない**（現状 0px。`node tests/shot.js` で計測できる）
- [ ] 既存テスト `node tests/smoke.js` が全項目通る
- [ ] `node tests/deadend.js` が全項目通る
- [ ] `node tests/shot.js` の全行が `縦あふれ:0px 横あふれ:0px`

## 6. やってはいけないこと

- ゲームロジック（`guess` / `finishRound` / スコア計算 / セーブ形式）に触れる
- 棒人間の**縦位置を動かす**（進捗バーの上に立つ設計。`track` の高さ 40px を増やすとモバイルで盤面が縮む）
- 色を画像に焼き込む
- 外部 CDN・Web フォント・アニメーションライブラリの追加（現在は依存ゼロ）
- 絵文字を使う（環境によって表示されないため、ゴール旗も CSS で描き直した経緯あり）

## 7. そもそも画像化すべきかの判断基準

**画像化する価値があるのは以下に当てはまるときだけ:**

- 手描きの中割りでしか出せない「ため」「戻り」の気持ちよさが欲しい
- キャラクターに固有の造形（髪・服・小物）を持たせたい
- 表情のバリエーションを増やしたい（現在は顔の中身がひらがな 1 文字のみ）

**当てはまらないなら CSS 版のまま調整するほうが良い。理由:**

- 現在アセット 0KB・依存 0 個。読み込み失敗も解像度問題も存在しない
- FEVER 色・被弾色をコードから自由に変えられる
- 角度や尺の微調整が CSS 1 行で済む（実際、本作業では「腕が顔に重なる」問題を数値 2 箇所の変更で解決した）
- 任意の拡大率で鮮明（`scale(1.12)` を後から足しても劣化しない）

判断に迷う場合は、まず **cheer（正解ジャンプ）1 モーションだけ**を画像化して A/B で比べること。
全モーションを作り切ってから比較しないこと。
